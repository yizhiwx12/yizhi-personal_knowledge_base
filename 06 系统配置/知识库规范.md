# 知识库规范

## 仓库根目录

`C:\Users\yizhi\Documents\yizhi的个人知识库`

## 目录分工

- `01 收件箱`：所有新内容的临时落脚点，等待分类和处理。
- `02 原始资料`：剪藏的网页、PDF、字幕等原文存档，保留来源材料以便查证。
- `03 提炼笔记`：从原始资料中拆分、提炼出的原子化概念笔记；按内容类型放入对应子目录：
  - `03 提炼笔记/概念`：定义、原理、观点等概念型笔记。
  - `03 提炼笔记/方法`：步骤、流程、技巧等方法型笔记。
  - `03 提炼笔记/案例`：实例、经验和具体应用案例。
- `04 主题索引`：主题地图和知识库导航入口，用于汇总主题下的重要笔记与链接。
- `05 我的产出`：基于知识库形成的文章草稿、周报、课程等个人产出。
- `06 系统配置`：笔记模板、知识库规范及 Agent 任务说明等维护知识库所需的配置文档。

## 笔记模板规范

新建笔记应使用 `06 系统配置/笔记模板.md`。每条笔记的 YAML frontmatter 必须包含以下字段：

- `title`：笔记标题。
- `type`：笔记类型，使用 `raw`（原始资料）、`note`（提炼笔记）或 `moc`（主题索引）。
- `source`：原始链接；没有链接时填写适当说明。
- `author`：作者；未知时填写“未知”。
- `created`：创建日期，格式为 `YYYY-MM-DD`。
- `tags`：标签列表，没有标签时填写空列表 `[]`。
- `status`：处理状态；新进入收件箱的笔记使用 `inbox`。

正文保留模板中的“摘要”“正文 / 要点”“相关笔记”“待办 / 延伸问题”四个部分，可按笔记内容填写。

## 标签维度

标签按以下维度组织，可按笔记内容添加多个维度的标签：

- 主题：使用 `#主题/主题名`，例如 `#主题/知识管理`。
- 类型：使用 `#类型/类型名`，例如 `#类型/方法论`。
- 状态：使用 `#状态/状态名`，例如 `#状态/待消化`。

## 命名规则

新笔记一律采用 `YYYY-MM-DD-标题.md` 格式，日期使用创建日期，例如 `2026-11-05-知识管理.md`。

## 图表规范

- 用 Markdown 表格整理并列比较、分类、参数或校核条件；列数保持适中，避免把整段说明塞进单元格。
- 用 Mermaid 表示清晰的步骤流程、因果关系或知识结构；图中术语应与正文一致。
- 曲线、波形和器件结构等需要精确形状的内容，使用 SVG 或 PNG 并在笔记中嵌入；曲线图标明坐标、单位和关键区域，示意图注明非比例或参数适用范围。
- 只在图表能帮助比较、判断或理解关系时添加；不重复正文已有的同类信息，原始资料中的图表及内容保持原样。

## 处理流程

1. 所有新内容先进入 `01 收件箱`。
2. 处理内容时补全笔记信息并确认来源；处理完成后，将网页剪藏、PDF、字幕等原始材料归档到 `02 原始资料`。
3. 从原始资料中拆出独立、可复用的知识点，按概念、方法或案例分别保存到 `03 提炼笔记` 下对应的子目录。
4. 根据需要更新 `04 主题索引`，并将文章草稿、周报或课程等整理到 `05 我的产出`。
